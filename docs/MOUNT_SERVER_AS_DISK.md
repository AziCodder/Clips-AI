# Сервер как диск в Windows (SSHFS)

Чтобы папка на сервере отображалась в проводнике как обычный диск (например `Z:`), и можно было создавать/редактировать файлы как на своём компе, используй **SSHFS**.

## Что нужно

- Рабочий SSH-доступ к серверу (по ключу или паролю).
- IP или hostname сервера (у тебя в `.vscode/sftp.json`: `31.207.55.254`).
- Пользователь: `deploy` или `root`, путь к проекту: `/home/deploy/clips` или `/root/clips`.

---

## Шаг 1: Установка WinFsp и SSHFS-Win

1. **WinFsp** (файловая система для Windows, нужна для SSHFS):
   - Скачай установщик: https://winfsp.dev/rel/
   - Установи (оставь настройки по умолчанию).

2. **SSHFS-Win** (драйвер, чтобы монтировать папки по SSH):
   - Вариант A: из Microsoft Store — поиск «SSHFS-Win» → установить.
   - Вариант B: с GitHub — https://github.com/winfsp/sshfs-win/releases — скачай последний `.msi`, установи.

**Важно:** отдельной программы «SSHFS-Win» в меню Пуск нет. После установки диск подключается через стандартный **Проводник → Этот компьютер → Подключить сетевой диск** (см. Шаг 2). Если нужна программа с полями «хост, пользователь, путь» — см. раздел «Опционально: GUI sshfs-win-manager» ниже.

**Проверить, что всё стоит:** Параметры Windows → Приложения → установленные приложения → в поиске введи «WinFsp» и «SSHFS». Должны быть в списке. После установки при необходимости перезагрузи ПК.

## Шаг 1.5: Узнать точный путь на сервере (если диск не подключается)

Подключись по SSH и выполни:

```bash
# Под кем залогинен и домашняя папка
whoami
echo $HOME

# Где лежит проект (если заходишь под deploy)
ls -la $HOME
ls -la $HOME/clips

# Или найти папку по имени
find /home -maxdepth 3 -type d -name "clips" 2>/dev/null
find /root -maxdepth 3 -type d -name "clips" 2>/dev/null
```

- Если `$HOME` = `/home/deploy` и проект в `$HOME/clips`, то полный путь: **`/home/deploy/clips`** → в Windows вводи **`\home\deploy\clips`**.
- Если проект в `/root/clips`, то в Windows: **`\root\clips`** и пользователь **root** в пути.
- Если путь другой (например `/home/deploy/projects/clips`) — в поле «Папка» используй его: `\home\deploy\projects\clips`.

## Шаг 2: Подключить папку сервера как диск

### Способ A: Через проводник (проще)

1. Открой **Проводник** (Win+E).
2. В левой панели правый клик по **«Этот компьютер»** → **«Подключить сетевой диск»**.
3. Выбери букву диска (например **Z:**).
4. В поле **«Папка»** укажи путь в формате SSHFS (обязательно **полный** путь на сервере):
   - Для пользователя `deploy` папка проекта: `/home/deploy/clips` → в пути должно быть **`\home\deploy\clips`** (не `\deploy\clips`):
   **Под пользователем deploy (проект в /home/deploy/clips):**
   ```text
   \\sshfs\deploy@31.207.44.254\home\deploy\clips
   ```
   **Под пользователем root — только сервер, домашняя папка root (/root):**
   ```text
   \\sshfs\root@31.207.44.254\root
   ```
   Под root к папке `/root/clips` (если есть):
   ```text
   \\sshfs\root@31.207.44.254\root\clips
   ```
   **Частая ошибка:** написать `\deploy\clips` вместо `\home\deploy\clips` — тогда Windows выдаёт ошибку 0x800704b3 (сетевой путь не найден).
5. Включи **«Входить в систему повторно»** (чтобы диск подключался после перезагрузки).
6. Нажми **«Готово»**.
7. Введи пароль пользователя (`deploy` или `root`), если попросит.  
   Если используешь SSH-ключ, SSHFS-Win может запросить ключ — укажи путь, например:  
   `C:\Users\Абдул-Азиз\.ssh\id_ed25519`.

После этого в «Этот компьютер» появится диск **Z:** (или выбранная буква) — это и есть папка с сервера. Создание/удаление/редактирование файлов там = работа на сервере.

### Способ B: Через net use (если знаешь пароль)

В **PowerShell** или **cmd** (подставь свой пароль или используй ключ по инструкции к SSHFS-Win):

```powershell
net use Z: "\\sshfs\deploy@31.207.44.254\home\deploy\clips" /persistent:yes
```

Пароль введи по запросу. Букву `Z:` можно заменить на любую свободную.

---

## Использование

- В **Проводнике** открываешь `Z:` (или свою букву) — видишь файлы проекта на сервере.
- Создаёшь папки и файлы как на обычном диске — они сразу появляются на сервере.
- В **Cursor**: **File → Open Folder** → выбери `Z:\` (или `\\sshfs\deploy@31.207.55.254\home\deploy\clips`) — будешь редактировать файлы «на сервере» прямо из Cursor.
- Отключить диск: правый клик по диску в проводнике → **«Отключить»**.

---

## Если используешь SSH-ключ (без пароля)

В стандартном диалоге «Подключить сетевой диск» Windows не всегда показывает выбор ключа. Варианты:

1. **SSHFS-Win (реестр)**  
   Некоторые сборки SSHFS-Win подхватывают ключ из `~/.ssh/` при совпадении хоста и пользователя. Убедись, что в `C:\Users\<ТвойЛогин>\.ssh\config` есть запись для этого сервера с `IdentityFile`.

2. **Пароль от ключа**  
   Если ключ с паролем (passphrase), при монтировании его могут запросить один раз.

## Ошибка 0x800704b3 при любом пути (и deploy, и root)

Если и `\\sshfs\deploy@...\home\deploy\clips`, и `\\sshfs\root@...\root` дают одну и ту же ошибку **0x800704b3**, путь и пользователь ни при чём: Windows не подхватывает протокол **sshfs**. Что сделать по шагам:

1. **Проверить установку**  
   Параметры → Приложения → установленные приложения. Должны быть **WinFsp** и **SSHFS-Win**. Если кого-то нет — установи с https://winfsp.dev/rel/ и https://github.com/winfsp/sshfs-win/releases (или из Microsoft Store: «SSHFS-Win»).

2. **Перезагрузка**  
   После первой установки или обновления WinFsp/SSHFS-Win обязательно перезагрузи ПК.

3. **Попробовать sshfs-win-manager**  
   Программа сама поднимает диск и передаёт учётные данные драйверу. Скачай: https://github.com/evsar3/sshfs-win-manager/releases (например `SSHFS-Win-Manager-Setup-1.3.0.exe` или новее). Запусти от имени администратора (правый клик → «Запуск от имени администратора»), создай подключение (хост `31.207.44.254`, пользователь `deploy` или `root`, путь `/home/deploy/clips` или `/root`), укажи пароль и нажми Mount. Если и так 0x800704b3 — значит драйвер на твоей системе не регистрируется (антивирус, политики, другая ОС).

4. **Обход без диска**  
   Работать с файлами на сервере можно и так:
   - **Cursor + Remote SSH**: подключение к хосту → открыть папку на сервере (см. [CURSOR_REMOTE_SSH.md](CURSOR_REMOTE_SSH.md)).
   - **SFTP в Cursor**: правки локально, при сохранении файл уезжает на сервер (у тебя уже настроен `.vscode/sftp.json`).

---

## Возможные проблемы

| Проблема | Что сделать |
|----------|-------------|
| **0x800704b3 при любом пути** | См. раздел выше: проверка WinFsp/SSHFS-Win, перезагрузка, sshfs-win-manager. |
| Нет пункта «Подключить сетевой диск» или «Папка» не принимает `\\sshfs\...` | Убедись, что установлены и WinFsp, и SSHFS-Win. Перезагрузи ПК. |
| «Сетевой путь не найден» | Проверь IP, логин и путь (слэши: `\` в пути Windows для SSHFS — `\deploy@IP\home\deploy\clips`). |
| Диск «висит» или не открывается | Обрыв сети или сервер недоступен. Отключи диск (правый клик → Отключить), проверь `ping 31.207.44.254` и SSH. |
| Медленно открываются папки | По сети всё идёт через SSH — это нормально. Для тяжёлых операций с тысячами файлов SFTP или Remote SSH могут быть быстрее. |

## Опционально: GUI sshfs-win-manager

Отдельного приложения «SSHFS-Win» в меню Пуск **нет** — только драйвер. Если стандартное «Подключить сетевой диск» даёт 0x800704b3, имеет смысл попробовать **sshfs-win-manager** (программа с полями хост, пользователь, путь, буква диска):

1. Убедись, что установлены **WinFsp** и **SSHFS-Win** (см. Шаг 1).
2. Скачай **sshfs-win-manager**: https://github.com/evsar3/sshfs-win-manager/releases — установщик или `.exe`.
3. Запусти **от имени администратора** (правый клик по exe → «Запуск от имени администратора»). Добавь подключение: хост `31.207.44.254`, пользователь `deploy` или `root`, путь `/home/deploy/clips` или `/root`, буква диска `Z:`, укажи пароль — нажми Mount.

Если и так ошибка — драйвер SSHFS на этой Windows не работает; остаётся Remote SSH или SFTP в Cursor.

---

## Безопасность

- Пароль в `net use` не сохраняй в скриптах и не коммить в репозиторий.
- Лучше использовать SSH-ключ и, при необходимости, ключ без passphrase только для этого ПК (или с passphrase и вводом при монтировании).

После настройки сервер будет отображаться в «Мой компьютер» как обычный диск, и ты сможешь работать с файлами на нём как на простом компе.
